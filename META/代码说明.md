# META_HRL 代码说明

本文档面向第一次打开本仓库的读者。建议先理解“项目把什么问题交给环境”，再沿着
“场景 -> 物理层 -> 环境 -> PPO 训练 -> 评估”这一条主线阅读代码，而不是从某个
训练脚本直接向下追踪全部实现细节。

## 1. 这套代码在做什么

项目模拟一个下行无线系统：基站有 128 根 ULA 天线，服务 6 个单天线用户。用户可能处于近场或远场，并经历莱斯衰落。代码让强化学习策略决定 RSMA 的资源分配，以提升总速率和公平性、减少 QoS 缺口。

系统中有三种逐步增强的任务：

| 层级 | 要解决的决策 | 主要环境 | 主要训练入口 |
| --- | --- | --- | --- |
| Flat RL | 单公共流的私有/公共功率与公共率分配 | `OneStepRSMAEnv` | `train_flat_ppo` |
| HRL | Manager 分组，Worker 做组 RSMA 资源分配 | `HierarchicalRSMAEnv` | `train_staged_hrl_worker`、`train_manager_ppo` |
| Meta-PPO | 在不同慢变化任务间，利用交互历史形成 context | `ContextualWorkerTrainingEnv` | `train_meta_ppo` |

这里的“任务（task）”不是一个单独的信道样本，而是一类慢变化环境分布。例如近场用户
比例、莱斯 K 因子、路径损耗指数、噪声和 QoS 目标固定后，可以从该任务中不断采样快速
变化的信道 episode。

## 2. 最短阅读路径

如果只想先理解主功能，推荐按下面顺序打开文件：

1. `src/meta_hrl/envs/rsma_env.py`：最小可运行问题，了解观测、动作、奖励如何形成。
2. `src/meta_hrl/envs/task_sampler.py`：了解一个无线场景如何生成。
3. `src/meta_hrl/rsma/constraints.py`、`precoding.py`、`signal_model.py`、`rate.py`：了解
   一个动作如何变成可行资源分配和通信速率。
4. `src/meta_hrl/training/train_flat_rl.py`：了解 Stable-Baselines3 PPO 如何接入环境。
5. `src/meta_hrl/envs/hierarchical_env.py`：了解分组与资源分配怎样拆成两层。
6. `src/meta_hrl/envs/contextual_worker_env.py`：了解 Meta-PPO 如何把历史 context 加入状态。
7. `src/meta_hrl/cli.py`：了解命令行实验如何调度训练、基准与统计分析。

## 3. 总体数据流

```text
配置 / 随机种子
       |
       v
TaskSampler 或 MetaTaskSampler
       |
       v
RSMAScenario（信道、用户几何、QoS 等）
       |
       +--> encode_observation() --> 策略观察值
       |
       v
PPO 动作 logits
       |
       +--> 约束投影（softmax / 固定槽位）
       |
       v
预编码 -> SINR -> 公共率和私有率 -> 用户速率
       |
       v
reward、info、下一观察值
```

HRL 额外插入一层 Manager：Manager 先从候选分区中选择用户分组，Worker 再在该分组下
输出资源动作。Meta-PPO 则在 Worker 观察值尾部追加由历史 transition 得到的 context。

## 4. 配置和运行入口

### 配置目录

`configs/` 保存默认参数，不会在训练时自动被所有 Python API 读取；它主要用于记录和
复现实验设定。常用文件如下：

| 文件 | 内容 |
| --- | --- |
| `configs/channel/rician_near_far.yaml` | 28 GHz、128 天线、用户范围、近远场距离、莱斯参数 |
| `configs/rsma/default.yaml` | 总功率、噪声、RZF/MRT、单公共流动作形式 |
| `configs/environment/default.yaml` | 单步环境的观测、动作与奖励权重 |
| `configs/training/default.yaml` | PPO rollout、batch、网络宽度和分阶段 HRL 参数 |
| `configs/experiments/meta_hrl_mixed_near_far.yaml` | 元任务维度与训练/验证/OOD 划分说明 |

### Python 与 CLI 入口

- 包入口：`src/meta_hrl/__init__.py`
- 命令行入口：`src/meta_hrl/cli.py`，安装后命令为 `meta-hrl`
- 训练与评估导出：`src/meta_hrl/training/__init__.py`
- 环境导出：`src/meta_hrl/envs/__init__.py`

可先运行下面的命令查看可用工作流：

```bash
meta-hrl --help
meta-hrl train-meta --help
```

## 5. 场景与信道：从用户位置到 CSI

### `channel/`：物理信道基础

| 文件 | 核心对象/函数 | 作用 |
| --- | --- | --- |
| `geometry.py` | `ULAConfig`、`classify_near_field` | 描述 ULA，坐标转换，按 Rayleigh 距离判定近远场 |
| `far_field.py` | `ula_los_steering_vector` | 生成远场平面波导向矢量 |
| `near_field.py` | `ula_near_field_los_steering_vector` | 生成近场球面波导向矢量 |
| `rician.py` | `sample_rician_channel` | 合成 LoS 与复高斯 NLoS，生成莱斯信道 |
| `validation.py` | 信道诊断函数 | 检查范数、近远场差异、用户相关性等数值性质 |

### `envs/task_sampler.py`：生成一个场景

`ScenarioSamplerConfig` 定义用户数、天线数、距离/角度范围、QoS 等参数。
`TaskSampler.sample()` 返回不可变的 `RSMAScenario`，包含：

- `channels`：形状约为 `(K, M)` 的复信道矩阵；
- `ranges_m`、`angles_rad`、`near_field_mask`：用户几何和近远场标签；
- `path_loss_linear`、`k_factors_linear`：大尺度衰落与莱斯因子；
- `qos_rate_targets`：每个用户的目标速率。

### `envs/observation_encoder.py`：将场景交给神经网络

`encode_observation(scenario)` 将复 CSI 的实部/虚部与几何元数据拼接为 `float32` 向量。
默认 `K=6`、`M=128` 时，单步环境的长度为 1572。请注意：这是给神经网络的扁平表示，
不是物理层内部使用的信道矩阵；物理计算仍使用 `scenario.channels`。

## 6. RSMA 物理层：从 logits 到 reward

单公共流环境的 `OneStepRSMAEnv.step()` 是最值得细读的一段主流程：

```text
13 维 action logits
  -> project_action_to_resource_allocation()
  -> one_layer_rsma_precoders()
  -> one_layer_rsma_signal_terms()
  -> one_layer_rsma_rates()
  -> Jain 公平性、QoS gap、reward
```

### `rsma/` 的职责

| 文件 | 关键内容 | 阅读时关注什么 |
| --- | --- | --- |
| `constraints.py` | `ResourceAllocation`、`project_action_to_resource_allocation` | 用稳定 softmax 将 logits 转为非负且总和受限的功率/公共率分配 |
| `precoding.py` | `one_layer_rsma_precoders` | 为公共流与私有流构造 MRT 或 RZF 波束 |
| `signal_model.py` | `one_layer_rsma_signal_terms` | 计算解码公共流、私有流时的信号和干扰项 |
| `rate.py` | `one_layer_rsma_rates` | 从 SINR 得到速率，并检查公共率分配是否不超过物理公共率 |
| `baselines.py` | `equal_power_rzf`、`fixed_common_rsma` | 不使用 RL 的可比较物理基线 |
| `group_rsma.py` | 组公共流的投影、预编码、速率 | HRL 环境使用的多组版本 |

单公共流动作的结构是 `2K+1=13`：前 7 项在 6 个私有流和 1 个公共流之间分配总功率，
后 6 项分配物理公共率。环境先根据功率得到“公共率最多有多少”，再投影公共率动作，
因此策略不能违反公共率预算。

默认奖励为：

```text
reward = sum_rate_weight * sum_rate
       + fairness_weight * Jain_fairness
       - qos_gap_weight * sum(max(qos_target - user_rate, 0))
```

完整的中间结果会放在 `info` 中，例如 `sum_rate`、`user_rates`、`qos_gaps` 和
`power_allocation`。调试策略时，优先打印这些量，而不是只看 reward。

## 7. 三类环境如何使用

### A. `OneStepRSMAEnv`：Flat RL

文件：`envs/rsma_env.py`

- `reset(seed=...)`：采样一个静态场景并返回观测；
- `step(action)`：只允许调用一次，随后 `terminated=True`；
- `action_space`：`Box(shape=(13,))`；
- 用途：把“给定场景的一次资源分配”作为最小 PPO 基线。

### B. `HierarchicalRSMAEnv`：HRL 的底层物理环境

文件：`envs/hierarchical_env.py`

此环境把 Manager 和 Worker 的接口显式分开：

```python
observation, info = env.reset(seed=42)
observation, info = env.set_manager_action(partition_index)
observation, reward, terminated, truncated, info = env.step(worker_action)
```

- Manager 动作：候选分区索引。6 个用户共有 203 个规范集合分区；候选列表由
  `grouping/candidate_groups.py` 的 `enumerate_candidate_partitions()` 生成。
- Worker 动作：`3K=18` 维 logits，依次为 6 个私有功率、6 个组公共功率、6 个组内公共率。
- `high_level_interval`：每隔多少个 Worker step 才允许 Manager 更新一次分区。
- `episode_length`：一个多步 episode 的总 Worker step 数。
- 分区改变时加入 `partition_switch_penalty`，防止无意义频繁切换。

`group_rsma.py` 中的 `active_group_slots()` 以每组最小用户编号确定该组的公共流槽位。
没有对应组的槽位会被置零，因此无论分组怎样变化，Worker 始终输出 18 维动作；这是避免
变长动作空间和组标签置换的关键设计。

### C. `ContextualWorkerTrainingEnv`：Meta-PPO

文件：`envs/contextual_worker_env.py`

它内部创建 `WorkerTrainingEnv`，但将 Worker 原始观测扩展为：

```text
增强观测 = Worker 原始观测 + 7 维任务 context
```

在 `reset(options={"task_id": ..., "task_seed": ...})` 时，环境通过 `MetaTaskSampler`
生成指定训练、验证或 OOD 任务。每次 `step()` 都将 transition 按 task ID 写入
`TaskContextBuffer`；随后 `MetaContextEncoder` 根据该任务最近的历史生成 context。

这意味着不同任务不会混用经验。评估少样本适应时，也需要为每个 support budget 使用独立
context buffer，项目的 `evaluate_meta_adaptation()` 已遵守这一约束。

## 8. 分组模块与训练包装器

### `grouping/`

- `candidate_groups.py`：定义 `UserPartition`，规范化分区，并枚举候选分区。
- `heuristic.py`：从距离、角度、近远场标签和信道相关性计算分组亲和度；
  `select_heuristic_partition()` 选择一个分区。
- `metrics.py`：当前是预留模块。

### `envs/worker_training_env.py` 与 `manager_training_env.py`

`WorkerTrainingEnv` 将 `HierarchicalRSMAEnv` 包装为标准 Gymnasium Worker 环境。它可接收
固定分区或启发式 Manager，并在观察中加入分区成员关系特征。

`ManagerTrainingEnv` 则反过来把一个已训练 Worker 当作预测器：Manager 每执行一个离散
分区动作，包装器用冻结 Worker 连续运行一个高层区间，将累计回报返回给 Manager PPO。
这就是“先训练 Worker，再冻结 Worker 训练 Manager”的两阶段流程。

## 9. 训练、评估与实验分析

### 训练文件

| 文件 | 入口 | 作用 |
| --- | --- | --- |
| `training/train_flat_rl.py` | `train_flat_ppo` | 在单步环境训练连续动作 PPO |
| `training/train_hrl.py` | `train_staged_hrl_worker` | 在固定/启发式 Manager 下训练 Worker |
| `training/train_hrl.py` | `train_manager_ppo` | 冻结 Worker 后训练离散 Manager |
| `training/train_meta_hrl.py` | `train_meta_ppo` | 在任务间轮换 episode，训练 context-conditioned Worker |

这些函数的配置 dataclass（如 `FlatPPOConfig`、`StagedHRLConfig`、`MetaPPOConfig`）是修改
训练步数、PPO rollout、输出目录和随机种子的首选位置。

### 评估和统计文件

| 文件 | 核心入口 | 输出/用途 |
| --- | --- | --- |
| `training/evaluate.py` | `evaluate_flat_policy`、`evaluate_physical_baselines` | Flat PPO 和物理基线的统一指标 |
| `training/evaluate_hrl.py` | `evaluate_staged_hrl_worker` | Worker 阶段评估 |
| `training/evaluate_meta_hrl.py` | `evaluate_meta_adaptation` | validation/OOD 的 support-episode 适应曲线 |
| `training/benchmark_meta_hrl.py` | `run_meta_ppo_benchmark` | learned context 与 raw context 的配对多 seed 基准 |
| `training/significance_meta_hrl.py` | `analyze_meta_ppo_significance` | bootstrap CI 与 sign-flip 显著性检验 |
| `training/sensitivity_meta_hrl.py` | `run_meta_ppo_sensitivity` | context 容量、特征维度、OOD shift 网格 |
| `training/analyze_*.py` | 分析函数 | 将 JSON 导出为 CSV、SVG 和差异摘要 |

训练结果通常写入 `outputs/`：模型 checkpoint 为 `.zip`，TensorBoard 日志在 `logs/`，基准和
分析结果为 JSON/CSV/SVG。不要把不同实验写到同一个输出目录，否则同名 checkpoint 可能
被覆盖。

## 10. Meta-PPO 中的 raw 与 learned context

这两个概念容易混淆：

- **raw deterministic context**：`MetaContextEncoder` 从同一任务的最近 transition 计算
  7 维确定性统计量；策略直接使用拼接后的观测。
- **learned context feature branch**：`agents/learned_context.py` 的
  `ContextConditionedFeaturesExtractor` 分别用可训练 MLP 编码原始 Worker 状态与上述
  7 维 context，再拼接后交给 PPO actor/critic。

因此“learned context”并不表示一个端到端贝叶斯后验或 PEARL 风格 latent posterior；在
当前实现中，transition 到 7 维 context 的汇总仍是确定性的，学习发生在 PPO 网络对
context 特征的后续表示阶段。

## 11. 测试如何帮助理解代码

`tests/` 与源代码模块基本一一对应，适合作为可执行示例：

- `test_rsma_env.py`：单步环境的 API、动作约束、reward 与 info；
- `test_group_rsma.py`、`test_candidate_groups.py`：组公共流和分区规则；
- `test_train_hrl.py`、`test_train_manager.py`：两阶段 HRL 训练接口；
- `test_meta_context.py`、`test_contextual_worker_env.py`、`test_train_meta_hrl.py`：任务隔离、
  context 拼接与元训练；
- `test_benchmark_meta_hrl.py`、`test_significance_meta_hrl.py`、
  `test_sensitivity_meta_hrl.py`：实验输出与统计分析。

修改物理层、环境接口或观测/动作形状后，应优先运行对应测试，再运行全量测试：

```bash
python -m pytest tests/test_rsma_env.py
python -m pytest
```

## 12. 修改代码时最重要的约束

1. **物理可行性不能交给策略学习。** 功率、公共率预算和禁用组槽位由投影函数强制满足。
2. **Gymnasium 调用顺序必须正确。** 单步环境只能 `reset -> step` 一次；HRL 环境必须
   `reset -> set_manager_action -> step`。
3. **动作和观察维度是接口契约。** 单公共流是 13 维，组 Worker 是 18 维；改变它们会影响
   环境、训练器、checkpoint 和测试。
4. **任务历史必须隔离。** 写 context 时必须携带正确的 `task_id`，不能让 validation/OOD
   transition 混入训练任务。
5. **实验要保证可复现。** 显式设置训练 seed、task seed 和输出目录；基准比较应使用配对
   随机种子。

## 13. 常见阅读误区

- `OneStepRSMAEnv` 与 `HierarchicalRSMAEnv` 不是同一任务的简单循环版本：前者是单公共流
  Flat RL 基线，后者使用组公共流、历史速率和 Manager 分区。
- `WorkerTrainingEnv` 是训练包装器，不是新的物理模型；实际的物理计算仍在
  `HierarchicalRSMAEnv` 和 `rsma/group_rsma.py`。
- `meta_task_sampler.py` 定义慢变化任务分布，`task_sampler.py` 定义该任务中的具体无线场景。
- `outputs/` 中的结果是已运行实验的工件，不是训练代码的输入依赖。

掌握上述主线后，再根据你的目标深入阅读：想改信道就从 `channel/` 开始，想改奖励或动作
就从对应环境和 `rsma/constraints.py` 开始，想改 PPO 或实验协议就从 `training/` 开始。
